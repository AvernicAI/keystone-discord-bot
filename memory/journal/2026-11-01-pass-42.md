## Behaviour, exactly

1. `setup` reads effective settings and counts; `enabled` and `max_threads`
   write through the shared settings service and are re-validated by the module
   schema.
2. `open` writes the thread and its first message together. A member with an
   active thread is refused and the refusal names that thread.
3. `reply` resolves the caller to the member or staff side. The first staff
   reply claims the thread. A closed thread refuses.
4. `transcript` reads live rows, or the stored archive after a close; it clears
   the caller-side unread counter. Another member gets the same refusal as a
   missing thread.
5. `close` builds the canonical JSON, computes SHA-256, and stores transcript,
   checksum and message count in one conditional update. A second close refuses
   and writes nothing.
6. `stats` reads thread states, messages, staff unread and up to ten active
   thread ids — the ids are how staff can act on the queue.
7. A disabled module refuses member `open` and member `reply` but lets staff
   drain an existing thread.

## What we tried and rejected

- **Store a thread as a settings blob.** Rejected: no uniqueness, no ownership
  check, no ordered append and no single-write archive.
- **A separate `claims` table or a seventh `claim` subcommand.** Rejected: the
  plan's six names are the surface, and the first staff reply is already the
  moment a human takes the thread.
- **Delete messages on close.** Rejected: close archives, it does not rewrite
  history; the archived read must survive pruning.
- **Read state, then update.** Rejected: two closes could both read `open` and
  both write. The conditional update is the guarantee.
- **A different refusal for "not yours".** Rejected: that confirms existence.
- **DM/thread relay in this pass.** Rejected: it needs a delivery port and a
  gateway message handler, and the MCP bot cannot prove the DM half. The inbox
  is real; the relay is named open.
- **Stats as counts only.** Rejected after the first draft: staff could not
  discover a thread id to answer. The active queue is now part of the same
  subcommand, read from the same rows.
- **Include modmail in the guild export bundle now.** Deferred: the portability
  bundle has its own schema and receipt tests; `/modmail transcript` is the
  dedicated read today.
