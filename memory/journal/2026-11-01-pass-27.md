# Pass 27 — environment check and the synthetic slash harness

**Date:** 2026-11-01 · **Phase:** P7 · **Branch:** main

## Why this pass

Pass 26 made the command tree real and left one named gap: no automated path
crossed the real slash adapter, because the Discord MCP cannot invoke an
application command. This pass adds that harness and checks whether the new
`.env` can move the live window off the in-memory fallback.

## What changed

### The new `.env` is not a working real-store window

The file is present and parses. No values are printed here. The relevant gates
are set, and the endpoints are local:

```text
DATABASE_URL  postgres  localhost:5432  db=/keystone
REDIS_URL     redis     localhost:6379  db=/
```

They are **not usable on this machine**:

```text
$ pnpm db:migrate
AggregateError [ECONNREFUSED]
    at internalConnectMultiple (node:net:1430:18)
    at afterConnectMultiple (node:net:2099:7)

Redis ping: Connection is closed
  (ioredis could not connect to localhost:6379)
```

Additional checks:

- `docker` is not installed (`/usr/bin/bash: docker: command not found`).
- `Get-Service` finds no Postgres, Redis or Docker service.
- `netstat` shows no listener on 5432 or 6379.

The live bot therefore stays in the explicitly logged memory window:

```text
DATABASE_URL= REDIS_URL= pnpm start
database: memory · cache: memory · queue: in-process
```

The fallback cannot be retired in this live window. That is a local
infrastructure blocker, not a code pass: `pnpm check` and `pnpm build` do not
need either service.

The Ollama integration is up. `qwen3:8b` and `qwen3-embedding:0.6b` are
installed; `/v1/embeddings` returned 1024 dimensions and `/api/chat` answered in
about 8 seconds. The first bot `!ai chat` after boot hit the provider's hard
30-second abort while the model was cold:

```text
TimeoutError: The operation was aborted due to timeout
```

A retry after warm-up succeeded:

```text
!ai chat value="Reply with exactly: keystone"
AI chat — keystone

AI can be wrong. A human decides any action.
```

That cold-start edge is recorded, not hidden. The 30-second provider timeout is
unchanged in this pass.

### The synthetic slash harness

`apps/bot/src/interaction-harness.test.ts` builds the nested payload Discord
sends for `/mod ban user:@target reason:"posting raid invites" dry_run:false` and
feeds it through:

```text
ChatInputCommandInteraction-shaped object
  → asInteractionLike (the real adapter)
  → dispatchCommand (the real registry, guards, settings and module)
  → /mod ban
  → case store + ModerationActions.ban
```

It asserts the ban port received
`ban:guild-1:target-1:posting raid invites`, case #1 exists with the right reason
and state, and the reply says the case was recorded. A second test changes the
subcommand to an unknown path and asserts `dispatchCommand` returns
`unknown-command` before any side effect.

This is deliberately **not** a second fake command implementation: it imports
the real `modules` registry and the real adapter. It is still a structural
harness, not a gateway connection; Discord's actual `InteractionCreate` delivery
remains the one unobserved surface.

### The duplicate-reply incident

The first live check after restart showed **two identical embeds** for one
`!help` or `!mod history`. The MCP transcript proved it was not a handler bug:
two separate bot process trees were alive from the earlier restart sequence.

Both trees were stopped (PID trees 10172 and 13680), one `pnpm start` was
launched, and the transcript was repeated:

```text
!mod history
AI Team — Recent cases / No matching cases.   (exactly one reply)

!help search query=ban
AI Team — Matches for `ban`:                    (exactly one reply)
`/mod ban` — Ban a member with a case and reason.
```

One bot, one reply. The live process was stopped at the end of the pass.

## What we tried and rejected

- **Treat the configured localhost URLs as live.** Rejected: `db:migrate` gets
  `ECONNREFUSED`; Redis reports `Connection is closed`; no listener, service or
  Docker exists. Falling back silently would make a memory-mode proof look like
  a real-store proof.
- **Use PGlite as the “real Postgres” proof.** Rejected: the request was to prove
  the configured integration, and PGlite is the token-free test engine, not the
  configured server.
- **Invoke a real slash command with the MCP.** Rejected: the MCP exposes
  message/channel/member tools only; no application-command tool. The install
  permission is a client permission, not an API.
- **Keep the existing FakeInteraction test as the proof.** Rejected: it bypasses
  `asInteractionLike`, the exact place where nested subcommand options were
  previously dropped.
- **Leave both bot processes running.** Rejected: two sessions double every
  gateway event. One process is the correct live shape.
