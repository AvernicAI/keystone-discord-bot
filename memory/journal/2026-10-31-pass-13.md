# Pass 13 — Portability: export, restore, receipts and honest imports

## What changed

- Added `packages/importer`: versioned `keystone.export` v1 bundle, canonical
  SHA-256 checksum, row/unique counts, dry-run diff, narrow merge, 24-hour
  rollback, deletion receipts, level file parsers, transcript normalizers and a
  read-only drift report. See [[ADR-0015-portability-bundles-and-receipts]].
- Added `DrizzlePortabilityStore` and `createPortabilityStore` in `packages/db`.
  The store reads JSONB as text and parses once, preserving numeric strings; that
  is the same P0 fidelity bug class, now covered in a full export.
- Added `pnpm portability` (`scripts/portability.ts`) with export/import/levels/
  transcript/rollback/delete/drift. Destructive actions require `--yes`; exports
  are written `0600`.
- Added tests: `packages/importer/src/importer.test.ts` (12) and
  `packages/db/src/portability.test.ts` (7, including a 5,002-level round trip,
  failed-restore rollback, 24-hour rollback, deletion receipt and drift).
- Wrote [[Portability]], [[Portability-Runbook]] and [[Migration-Guides]], and
  marked the P5 feature rows shipped with evidence in `features.json`.

## What we tried and rejected

- **One JSON document per table / NDJSON.** Rejected for v1: one bundle is a
  checksum, a download and a lesson; the 25 MB cap is explicit. The manifest can
  add NDJSON in v2.
- **Concatenate all history in merge mode.** Rejected: duplicate case numbers and
  money without provenance look successful while lying. Merge is settings and
  levels only, with a warning.
- **Trust the vendor leaderboard fetch.** Rejected: only MEE6 is plausible, and a
  live pull is a terms and rate-limit problem. File import is the honest path.
- **Write first and verify afterwards.** Rejected: version, schema, checksum,
  guild identity and counts are checked before a row is touched; a post-write
  checksum is recorded but a mismatch is a loud warning, not a pass.
- **Keep deletion backups for "safety".** Rejected: a deletion that retains the
  content is not a deletion. The receipt stores counts and a hash only.
- **Auto-repair drift.** Rejected: a permission bug could delete the wrong channel
  during an incident. The report has `readOnly: true`.
- **Use the shared JSONB mapper for snapshot reads.** Rejected after the first
  drift test exposed `"333333333333333333"` becoming a number with lost
  precision. Text-cast plus one parse is the only round-trip-safe read.
