# Pass 83 — Music, for real: Lavalink, one durable queue, a live card and a dashboard remote

2026-11-06 · P7.5 · branch `feat/music-player`

## What changed

- **One real player behind the existing port.** `QueueMusicPlayback`
  (`apps/bot/src/music/playback.ts`) drives a Lavalink node through the small
  `VoiceNode` seam (`apps/bot/src/music/voice.ts`), and `ShoukakuNode` is the
  only file that knows Shoukaku or discord.js exists. The kernel port
  (`packages/kernel/src/music.ts`) gained `enqueue`, `resume`, `pause`,
  `setVolume`, `setLoop`, `shuffle`, `jump`, `remove`, `clear`, `snapshot` and
  `stop`; it still imports no discord.js, Drizzle, Redis or Shoukaku.
- **The durable queue is the play queue.** No new table and no migration:
  `community_records` with kind `music_queue`, key `default`, holds the ordered
  tracks, and `tracks[0]` is the current track until it ends or is skipped.
  `encoded` never leaves memory; persisting it would turn a 100-track row into
  megabytes of JSON.
- **A signed Components V2 card** (`modules/music/src/panel.ts`, publisher
  `apps/bot/src/music/panel.ts`): accent by state, a progress bar, the artist and
  length, up to five "up next" rows, a jump select over 25 tracks, and five
  buttons plus volume. Edits are serialised and throttled to one per 1.5 s, and
  a Discord `30046` (the message is gone) posts a fresh card instead of retrying
  a dead edit.
- **The dashboard is a remote, not a second player.** `musicPage` reads only
  bot-published state plus a heartbeat and the durable row;
  `musicControl` writes through Redis to the bot, appends one `music.control`
  audit row, and redirects with the bot's own message. The page is
  freshness-aware: a report older than 20 s is labelled "Last known state, not
  live" with controls disabled.
- **Command surface stays a budget-neutral root.** `/music` now has 14
  subcommands (play, add, queue, remove, clear, skip, stop, pause, resume,
  volume, loop, shuffle, jump, status). 20 global roots / 147 subcommands /
  167 actions / 4 context menus are unchanged.
- **The bundled node is honest configuration.** `lavalink/application.yml` runs
  http(s) sources only, and `compose.yaml` pins
  `ghcr.io/lavalink-devs/lavalink:4.2.2`. `.env.example` now ships the four
  `LAVALINK_*` defaults live instead of commented, because the documented
  quickstart starts that node; with no node, music refuses with the exact fix
  and the saved queue still works.

Shoukaku defaults we deliberately override: `resume: true` with a 60 s window
(Shoukaku defaults to no resume), `reconnectTries: 10` instead of 3,
`moveOnDisconnect: true`, `resumeByLibrary: true`, a 10 s REST timeout and a
15 s voice-connection timeout. Lavalink 4.2.x owns the voice socket and DAVE;
`@discordjs/voice` would duplicate the transport and add native opus and
encryption dependencies for no extra capability.

## Defects the playtest found, and the fixes

1. **"Resume" on a paused player restarted the queue.** The web form posted
   `action=resume`, which means "start the durable queue from its head"; the bot
   answered "Resumed." while the node stayed paused. The pause control now
   carries `value=false`, and `music-page.test.ts` asserts the page never emits
   `action=resume` for a paused player.
2. **Every control rendered a page up to 5 s stale.** Acting on Pause showed a
   page that still said `PLAYING`, because the web redirect rendered the last
   published snapshot. The bot now publishes the guild state *before* it writes
   the reply (`apps/bot/src/index.ts`), so the redirect reads the post-action
   state. Verified live: `Paused.` with the `paused` pill, `Resumed.` with
   `playing`.
3. **Appending while playing claimed "Started playback."** The play result
   already carries `playing` and `position`; the handler now answers
   `Queued at position N.` when nothing started, and a test pins it.
4. **A dead session's head was labelled `now`.** The queue pill keyed off "there
   is a last-known track" instead of "the session is live". It now keys off the
   live snapshot; a stale page test asserts no `now` pill and the `last report`
   pill instead.
5. **The documented quickstart could not play.** `.env.example` had all four
   `LAVALINK_*` values commented out, so `docker compose up lavalink` plus
   `pnpm start` still reported "no Lavalink node is configured". The defaults are
   now active and point at the bundled node, with a note that deleting them is a
   supported save-only setup.

## What we tried and rejected

- **`@discordjs/voice` + a local source resolver.** Duplicates the transport,
  adds native opus and DAVE dependencies, and still needs a resolver. Lavalink
  4.2.x already implements DAVE, and Discord enforces E2EE from 2026-03-01.
- **Ticking the progress bar every second.** A frame-accurate card is one edit
  per second per guild: a guaranteed 429. The card says "position is the node's
  last report, not a timer" and refreshes on state change.
- **Persisting `encoded`.** Makes the row self-sufficient but multiplies its
  size by roughly 20×. The head is re-resolved on resume instead; the documented
  cost is that a restart resumes at `0:00`.
- **Bundling a scraper or a YouTube source plugin.** Licence and terms risk for
  a feature the node already serves over http(s). `music.bundled-source` stays a
  non-goal.
- **Auto-resuming a dead session at boot.** A restart has no voice connection,
  so "resume" would be a fabricated state. The page says `Last known state, not
  live` and offers the explicit `↻ Resume saved queue`.
- **A second `music_queue` table.** The existing `community_records` row is
  already locked per guild, cap-checked and exported by the portability bundle;
  a new table would duplicate all three.
