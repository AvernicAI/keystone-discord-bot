## What we tried and rejected

- **Run slash commands through discord-mcp.** Not possible: SaseQ/discord-mcp
  exposes message/channel/role tools but no application-command invocation. The
  MCP account is a bot (`AllTheMons GPT`, bot: true), and Discord does not let a
  bot invoke another bot's slash command through the message API. A human client
  or a different harness is required. We did not fake an interaction.
- **Relax the bot-author gate globally.** Rejected: the gate prevents reply loops
  and bot spam. The seam is one exact id in one development guild, and has a
  test for the wrong guild.
- **Edit `.env`.** Not allowed and not necessary. The bot was started with
  `DATABASE_URL= REDIS_URL=` overrides because local services are absent. The
  user's `.env` still points at localhost services.
- **Use OpenAI defaults for Qwen3.** Rejected: `think:false` would be rejected
  by OpenAI, so it is an explicit, opt-in field.
- **Let Qwen3 think within the 300-token output budget.** Rejected: observed
  empty `content` with `finish_reason: length`; the bot's provider correctly
  treats empty content as an error instead of inventing an answer.
