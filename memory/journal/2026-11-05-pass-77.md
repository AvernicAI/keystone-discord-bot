# Pass 77 — the visual mission, and the first panel rebuilt on it

**Date:** 2026-11-05
**Phase:** P7.5
**Branch:** `feat/timeline-refresh`

## What changed

The bot already answers more questions per screen than Dyno, MEE6, Carl-bot or
ProBot. What it did not have was a way to keep improving that answer without
someone remembering to. This pass turns "make the visuals excellent" into three
artifacts that outlive the pass:

| Artifact | What it does |
| --- | --- |
| `memory/vault/01-Mission/Visual-Mission.md` | The charter: the grammar, the six-criterion rubric, and the rule that the weakest surface is the next pass. |
| `memory/machine/surfaces.json` | Twelve visible surfaces with a grade per criterion, the last live proof class and date, and the single next fix. |
| `scripts/audit-visuals.ts` (`pnpm audit:visuals`) | Runs inside `pnpm check`: coverage, evidence, palette and footer rules, then prints the weakest surface. |

Grading is per criterion, not a vibe: **structure**, **density**, **honesty**,
**freshness**, **action**, **copy**. An A requires a recorded live proof class,
so self-grading cannot drift away from the product.

## The grammar

`packages/ui` gained `theme.ts` — five accents keyed to a *state* (brand indigo,
green healthy, amber attention, red danger, slate empty) and one glyph set shared
by every module — plus six primitives in `grammar.ts`:

- `heading` — `## <glyph> Title` plus a `-#` context line naming scope.
- `facts` — one scannable line, at most five clipped parts.
- `row` / `rows` — `• <t:…:R> · what happened · \`source\``, capped at 12.
- `emptyState` — the fact and the command that creates the first row.
- `footer` — tiny provenance: read stamp, stores joined, stores missing.
- `actionRow` — at most three buttons, at most one primary.

Programmer errors throw (an empty title, a second primary button); data clips
(a long ticket subject, an absurd guild name). That split is what lets a test
assert the shape while a guild cannot make a panel fail to render. Thirty-one
tests cover the primitives, including markdown safety and the caps.

## The first conversion: the member timeline

`/mod history user:@member` is rebuilt on the grammar. The live run exposed two
copy defects that the old panel tests could not: the context line printed the
raw guild snowflake, and the footer read `Read: cases 2` in front of a count
list, which parses as a verb. The header now says `this server · events from
every module`; the footer says `Rows: cases 2`; and a member with no level row
reads `Level not recorded` instead of the database phrase `No level row`.

The panel's action row is the point of the pass. **↻ Refresh** is a signed,
guild-bound, 30-minute id. The route re-reads the same `memberTimelineLoader` the
command uses — one construction, so a button and the command it belongs to
cannot drift — and calls `interaction.update`, which edits the message in place
instead of posting a second one. Each render re-signs the id, so a panel stays
refreshable while it is being used and still expires when abandoned. The route
requires `ModerateMembers`: reading another member's cross-module history is a
staff view, and a member-facing button would be a privacy hole.

A bot built without a component signer still gets the read model; it simply
refuses to ship an unsigned button rather than rendering a dead control.

## One real bug found by using it

While driving the command in a real client, the dry-run refusal printed
`Set dryRun: false in moderation settings (or pass dry_run: false) to enforce.`
but `warn` had no `dry_run` option, so the sentence was a lie for exactly the
action being run. `warn` is the only punitive-shaped action with no external
call — it writes a case, never a Discord ban — so the override is safe there and
the option now exists, with a test that proves `dry_run: false` writes a case and
the default still writes nothing.

## Live proof

Class: **gateway** — a signed-in Discord web client, not the read-only MCP and
not a simulation.

- Two bot instances were running at once and both answered the same interaction,
  which is why earlier replies doubled and logged `Interaction has already been
  acknowledged` / `Unknown interaction`. Both were stopped; one fresh boot logged
  `commands current`.
- `/mod history user:@Mr Bubba` in `#general` of the development guild returned
  the converted panel: `this server · events from every module`,
  `Level not recorded · 0 coins`, `Cases 2 open · Tickets 0 open · Modmail 0 open`,
  two source-tagged rows (`Case #2`, `Case #1`), and the footer
  `Read … · 10/10 stores joined` / `Rows: cases 2` / the named omissions.
- Pressing **↻ Refresh** edited that same message in place (`(edited)` in the
  client) and stamped a new read time. That is the freshness and action criteria
  proven where they are actually used.

A real case also exists because of this run: `/mod warn` with `dry_run: false`
created case #1 with reason `live proof`, and the timeline read it from the
`cases` store. The dry-run default was exercised first and wrote nothing.

## What we tried and rejected

**Hand-writing each panel well.** Rejected. Twelve surfaces written by hand are
twelve chances to omit the footer, inline a hex or print a bare heading. The
primitives exist so consistency is the default and the audit can check it.

**A screenshot-diff visual test.** Rejected. Discord renders panels server-side;
there is no canvas to diff, and asserting pixels would test Discord's client, not
our layout. The ledger plus the primitives' character/line caps test the product
contract instead.

**Grading with the script.** Rejected. Taste stays in review; `audit:visuals`
only proves the ledger is complete, dated and self-consistent. It prints the
weakest surface and the fix, which is the next pass's brief.

**Converting all twelve surfaces at once.** Rejected. One surface per pass keeps
the live proof real and the diff readable; the ledger makes the queue visible so
"later" is a date, not a hope.

**A member-facing refresh button.** Rejected. Cross-module history is staff data;
the route requires `ModerateMembers` before the handler runs.

**Posting a new message on refresh.** Rejected. A moderator watching a member
should see the new case appear where they are already looking; `update` is the
whole point of the control.

**Keeping the old footer wording.** Rejected after seeing it live. `Read: cases 2`
reads as a verb followed by a count; `Rows: cases 2` reads as a table. The tests
were updated with the copy, not weakened around it.

**Adding a `dry_run` option only to `warn` and leaving the refusal text alone.**
Rejected the other way round: the refusal must stay true for every action, so the
option was added where it is safe instead of qualifying the sentence per action.

## What this taught

- A duplicate bot process is invisible in tests and obvious only in the client:
  every live session should count processes before reading a result.
- Driving Discord's composer by bulk text insertion destroys structured slash
  state; real keystrokes plus the option list are the only reliable way to fill
  options, and the UI is the fastest place to find copy defects.
- The audit's "weakest surface" line is more useful than a pass/fail: it makes
  the next pass a decision already made.
