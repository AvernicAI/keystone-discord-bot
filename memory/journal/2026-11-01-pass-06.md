# Pass 06 — P3 community

## What changed

- Added the `community` module: settings, in-memory store, leveling/economy
  services, welcome, reaction roles, starboard, giveaways, temporary voice,
  thread tickets, content tools, reminders, polls, feeds and stat channels.
- Added `/rank`, `/ticket` and `/tools`; the global ledger is now 9/100.
- Added `CommunityPort` (`CommunityStore` + `CommunityActions`) to the kernel and
  wired `Context.community` through dispatch and test fixtures.
- Added migration `0004_community_records`, the Drizzle store and the factory.
- Added the Discord action adapter and gateway/button/scheduler seam. Sends,
  threads, role toggles, voice creation, ticket transcripts, starboard reactions,
  giveaways, reminders and feed polls are routed through the module.
- Added P3 docs, ADR-0008, this journal and machine-state updates.

## What we tried and rejected

- **Thirteen kernel ports.** Too much wiring and test surface; one community port
  with typed methods and a separate action half is enough.
- **A table per feature.** Rejected in favour of `community_records` for panels,
  tags, feeds and giveaways; the typed XP/ledger/ticket spine stays.
- **A counter for money.** Rejected: balances are sums over `economy_ledger` with
  idempotency keys, so a retry cannot mint coins.
- **One utility root per feature.** Rejected: `/tools` is the hub; `/rank` and
  `/ticket` are the only mental models that earned their own roots.
- **Select-menu reaction roles in this pass.** Deferred with the open limitation
  documented; buttons are the tested path.
- **A local-only store.** Rejected: the Drizzle adapter is required for a real
  restart; PGlite tests prove the SQL path without a server.
