# Pass 24 — profanity / zalgo and the delete-mode proof

**Date:** 2026-11-01
**Phase:** P7 parity completion
**Commit:** `feat(moderation): add profanity and zalgo filters`

## The choice

`memory/machine/features.json` still listed `automod.profanity-zalgo` as open.
Dyno and Carl-bot both document word filters, and it is the remaining automod
row that can be proven through the real message path with one account. It won
over the other open P7 rows:

- **Panic mode** needs a guild-wide channel action and a live lockdown, which is
  too destructive for an unattended test guild.
- **Auto-responder** needs a persisted trigger store and a second event seam; it
  is a larger pass and a better follow-up than a half-built slice tonight.
- **Case export** and **goodbye messages** are smaller but less central to the
  "all-in-one" promise than content moderation.

The previous pass also left one named evidence gap: the link filter had only
been exercised in `alert` mode. This pass closes it with the real Discord
adapter, then restores the safe dev seed.

## What changed

### Settings

`modules/moderation/src/settings.ts`

| Key | Default | Meaning |
| --- | --- | --- |
| `automod.profanity` | `off` | `off`, `alert` or `delete` for an operator-owned word list |
| `automod.bannedWords` | `[]` | Up to 200 words or phrases; matched case-insensitively |
| `automod.zalgo` | `off` | `off`, `alert` or `delete` for excessive combining marks |
| `automod.zalgoThreshold` | `8` | Combining marks before a zalgo finding |

The list is empty by default. A fresh install is not given a word list that
somebody else chose; the operator owns the policy.

### Engine

`modules/moderation/src/security.ts`

- `bannedWordMatch` escapes every word, turns internal whitespace into `\s+`,
  and wraps the alternatives in Unicode-aware word edges:
  `(?<![\p{L}\p{N}_]) … (?![\p{L}\p{N}_])`. This is why `ass` does not match
  `class`, and a phrase can span any amount of whitespace.
- `combiningMarks` counts `\p{M}` code points. At or above the threshold, the
  finding is `automod.zalgo`; below it, the message is untouched.
- Both rules create the same `alert` or `delete-message` finding kinds as the
  link filter, so the coordinator, case store, appeal button and notification
  path are unchanged. Evidence is `{ match }` for a word and
  `{ combiningMarks, threshold }` for zalgo; the full message is not stored.

### Review action

`/mod filters` lists the newest link, profanity and zalgo cases with the rule,
state, target and reason. It is an action under the existing `/mod` root;
`/mod links` remains the link-only view. No new command, no budget change.

### Development fixture

`apps/bot/src/runtime.ts` seeds the in-memory dev guild with:

```ts
automod: {
  links: "alert",
  linkBlocklist: ["phish.test"],
  profanity: "alert",
  bannedWords: ["pineapple"],
  zalgo: "alert",
}
```

The security marker from pass 23 (`keystone-test:`) is reused, so one MCP bot
can drive the real gateway → coordinator path. Production has no seed and no
marker option.

## Live evidence

### The link filter actually deletes

For this check only, the dev seed was temporarily `dryRun: false` and
`automod.links: "delete"`. The bot booted in memory mode as `AI Team#5758` with
11 commands current. The MCP posted:

```text
keystone-test: https://login.phish.test/delete-me
```

The message ID returned by Discord was `1566361999544156190`. Three seconds
later `get_message` returned:

```text
10008: Unknown Message
```

The message was gone. `!mod links` showed the case that survived the deletion:

```text
Link-filter findings (newest first):
#1 · open · automod.link · <@1493685079468146808> · The link host login.phish.test is on this server's blocklist.
```

This closes the pass-23 gap: the delete branch, the real Discord action and the
case record all ran together.

### The safe seed

The temporary seed was reverted to the final one above (`links: "alert"`, no
`dryRun` override). A fresh process booted, and the same blocked link was posted:

```text
keystone-test: https://login.phish.test/safe-mode
```

This time `read_messages` still showed the message, and `!mod filters` reported:

```text
Content-filter findings (newest first):
#3 · alerted · automod.zalgo · <@1493685079468146808> · The message contains 16 combining marks; the limit is 8.
#2 · alerted · automod.profanity · <@1493685079468146808> · The message contains a blocked word or phrase.
#1 · alerted · automod.link · <@1493685079468146808> · The link host login.phish.test is on this server's blocklist.
```

The profanity fixture was:

```text
keystone-test: I really like pineapple pizza
→ #2 · alerted · automod.profanity
```

The zalgo fixture was a short word with 16 combining marks:

```text
keystone-test: z̸̸̸̸a̸̸̸̸l̸̸̸̸g̸̸̸̸o
→ #3 · alerted · automod.zalgo · 16 combining marks; the limit is 8.
```

An earlier zalgo attempt with five marks produced no case: the threshold is 8.
That negative result is useful; the check is not "any combining mark is evil".

The ordinary message `a classic assignment and apple pie` produced no case, so
the live filter did not flag a benign sentence. `!mod review case=2` changed the
profanity case to `reviewed`, and the next `!mod filters` read:

```text
#2 · reviewed · automod.profanity · ...
```

## What we tried and rejected

- **Substring matching.** Rejected: it is how `ass` ends up flagging `class`.
  The Unicode edge pattern is a little more code and a much better rule.
- **A remote word list or threat feed.** Rejected: it adds a network dependency,
  a privacy question and possibly a paid service. The list is local settings
  data.
- **Shipping a default profanity list.** Rejected: every server has a different
  line. The default is an empty list and `off`.
- **One mode for profanity and zalgo.** Rejected: combining marks are legitimate
  in many scripts. An operator may want word alerts without a zalgo heuristic,
  or a higher threshold.
- **A new `/filters` root.** Rejected: `/mod filters` costs no additional global
  command and keeps the review queue with the moderation hub.
- **Text-only zalgo detection via a regex length.** Rejected in favour of a
  counted mark threshold; it is easier to test and explain.
- **Locking the whole guild (panic mode) for a live demo.** Rejected for this
  pass: it is a separate capability and a destructive test on the only test
  guild.

## Limits

- The live delete proof used **link** mode. Profanity and zalgo use the same
  `delete-message` coordinator path but were exercised live in `alert` mode only.
- Word boundaries are deliberate: `pineapple` does not match `pineapples`, and
  leetspeak or homoglyph obfuscation is not normalised.
- The zalgo threshold is a heuristic. Scripts with many legitimate combining
  marks can trip it; raise the threshold or disable the rule.
- `/mod filters` reads the newest 25 cases. It is a review aid, not an export.
- There is no false-positive report or per-rule analytics yet; the
  `automod.false-positive-report` row remains open.
- The marker is test scaffolding and is never registered in production.
