# Pass 11 — Channel obfuscation hotfix

## What changed

- Added `apps/bot/src/channels.ts` with `isObfuscated()` and `resolveChannel()`.
  The resolver returns `ok`, `hidden`, `missing` or `error`, handles the
  `CHANNEL_OBFUSCATED` flag (`1 << 17`), the `___hidden___` name and Discord
  error codes 10003 / 50001 / 50013.
- Replaced all nine `channels.fetch` call sites in `moderation-actions.ts` and
  `community-actions.ts`. A hidden channel is now a named failure or a safe no-op
  instead of an exception.
- Added `scripts/audit-channels.ts` and wired it into `pnpm check`; it fails on a
  direct lookup outside `resolveChannel` or a `.channels.cache` identity use.
- Added six resolver tests.

## What we tried and rejected

- **Match hidden channels by name only.** Rejected: Discord calls the name a
  placeholder; the flag is the contract.
- **Treat 50001/50013 as generic errors.** Rejected: those are exactly the
  "hidden from the bot" cases an operator can fix, so they get a named reason.
- **Put the resolver in the kernel.** Rejected: it imports discord.js; the kernel
  must stay token-free.
- **Retry the fetch once.** Rejected: a hidden channel will stay hidden; a retry
  spends the invalid-request budget for nothing.
