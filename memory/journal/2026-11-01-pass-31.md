# Pass 31 — `/export` above the CLI, and a live file proof

**Date:** 2026-11-01
**Phase:** P7
**Commit:** pending at the time of writing
**Previous pass:** [pass 30](2026-11-01-pass-30.md)

## Why this root

The approved v1.0 plan had two roots left: `/export` and `/music`. `/export`
won because it reuses `packages/importer`, the `PortabilityService` and the
tables the bot already owns; `/music` would need a new external dependency and
a BYO Lavalink node to prove anything honestly. Portability is also the feature
no surveyed generalist bot documents, and the P5 service had only a CLI. The
operator who never opens a terminal still needs a way to take their server's
data with them.

## What changed

`/export` is one new root in the **setup** module:

| Subcommand | What it does |
| --- | --- |
| `guild` | Posts the verified `keystone.export` bundle as a JSON attachment, with counts and checksum in the reply. |
| `user` | Posts one member's cases, case events, tickets, levels, XP events and economy rows as JSON. |
| `import` | Reads a Discord attachment, verifies the bundle, previews by default; `dry_run:false` writes. |
| `delete` | Requires the exact guild id in `confirm`; deletes guild rows and backups in one transaction and returns a count-only receipt. |
| `drift` | Compares stored `channelId` / `roleId` / `categoryId` settings with the live gateway cache; read-only. |
| `rollback` | Restores the pre-import backup of an applied import by id. |

One root and six subcommands. Discord now reports **16 roots / 100 subcommands /
116 actions**; the budget gate is 16/100 roots.

### The shape

- `packages/kernel/src/export.ts` defines `ExportPort`, `AttachmentReader` and
  `ExportFacts`. The command knows nothing about Drizzle or discord.js.
- `apps/bot/src/export-port.ts` has the SQL adapter (the existing
  `PortabilityService` over `createPortabilityStore`) and the memory adapter.
  The memory adapter reads the live `InMemoryCaseStore`,
  `InMemoryCommunityStore` and `InMemoryAiStore`; it refuses import, delete and
  rollback with the exact missing prerequisite (`DATABASE_URL`) rather than
  pretending a transaction exists.
- `apps/bot/src/export-discord.ts` owns the two Discord boundaries: live guild
  facts from the gateway cache, and a CDN-only attachment reader capped at
  25 MB. A pasted arbitrary URL is refused before `fetch`.
- `ReplyInput` now carries `files`; `apps/bot/src/adapt.ts` turns them into
  `AttachmentBuilder`s and keeps an attachment option's CDN URL in the
  structural options map. The development `!` bridge uploads the same files.
- `InMemoryCommunityStore` now retains XP events (not only the projection) and
  exposes read-only `allLevels` / `allXpEvents` / `allLedger` / `allRecords`
  helpers. `InMemoryAiStore` exposes `allDocuments` / `allUsage`. These are the
  same rows the commands use, which is what makes a memory-mode export truthful.

No migration was needed. No new table, no second export service and no paid
service.

## What we tried and rejected

- **Embedding the JSON in an embed description.** Discord's 4,096-character
  embed limit truncates a real guild export. A file attachment is the only
  honest delivery; the command now says so.
- **Making `/export` SQL-only.** That would make the live root a row of
  "requires DATABASE_URL" messages and leave the user with no portable data in
  the supported memory mode. The memory adapter exports the rows that actually
  exist and refuses the three actions that need a transaction or a backup store.
- **A second portability service for Discord.** The SQL adapter constructs the
  same `PortabilityService` the CLI uses. One restore policy, two surfaces.
- **Fetching any URL from an attachment option.** That is an SSRF hole. The
  reader accepts only `cdn.discordapp.com` / `media.discordapp.net`, enforces
  HTTPS and caps the body at 25 MB before parsing.
- **Treating an import as applied by default.** Replace is destructive. The
  command defaults `dry_run` to true and prints the setting diff; only an
  explicit false writes.
- **Letting memory mode claim deletion or rollback.** It has no transaction and
  no backup policy, so it returns the exact missing prerequisite. A plausible
  success would be worse than a refusal.
- **Reading `guild.channels.cache` directly in the export adapter.** The
  channel-obfuscation audit rejected it, correctly: cache access belongs in one
  seam. The fix moved channel enumeration into `apps/bot/src/channels.ts` as
  `cachedChannels()` and left the audit strict, rather than adding an exception.

## Limits

- Live Discord slash `InteractionCreate` is still unobserved. The proof is the
  development `!` bridge through the real registry, guards, adapter and reply
  path; the attachment upload itself is real.
- `import`, `delete` and `rollback` are SQL-only. Their command paths are tested;
  no live Postgres or live slash run is claimed.
- Memory-mode exports omit member profiles and audit events because the
  in-memory stores never retained them. Settings are effective values, not raw
  override rows. Both warnings are in the reply and in the file's surrounding
  contract.
- `expectedAutoModRules` is empty in the live drift path; the report lists
  present AutoMod names but does not claim which rules should exist. The
  native AutoMod plan is the source for that future comparison.
