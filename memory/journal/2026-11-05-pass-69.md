# Pass 69 — `partial` and `liveScope` become real

**Date:** 2026-11-05
**Phase:** P7.5 (truth)
**Type:** memory schema, checks and prose correction. No product behaviour changed.

## Why

Pass 66's audit found the feature matrix using one word, `open`, for three
different states: absent, mostly shipped, and shipped-but-manual-only. It also
found 25 rows marked `liveVerified: true` with no evidence a reader could check.
That is the exact failure this project is built to avoid: a confident flag with
nothing behind it.

The approved plan put the schema and its checks in the same pass, because a
status that the gate does not understand is just a comment.

## What changed

### `status: partial`

`features.json` now has a fifth status. A `partial` row must carry:

- `shippedParts`: the visible capability that exists, as concrete sentences;
- `openParts`: the named capability that does not;
- `openReason`: why the missing part is missing;
- `evidence`: at least one path that exists.

Four rows moved from `open`:

| Row | Ships | Still open |
| --- | --- | --- |
| `community.social-feeds` | RSS/Atom polling, GUID dedupe, posting on the community tick | YouTube, Twitch and Kick adapters |
| `operations.web-dashboard` | sessions, widgets, audited writes, fleet, templates, portability, analytics, tokens, webhooks | a live Discord OAuth round trip |
| `events.reminders` | manual `/event remind` with bookkeeping | scheduled delivery, per-member timezones |
| `events.ics-export` | checksummed `keystone.events` JSON export | ICS serialization and a consumer |

`open` is now reserved for a row with nothing shipped, and the gate rejects
`open` + `liveVerified: true` in either direction. That closes audit A-13 and
A-15, and makes A-20 impossible to reintroduce.

### `liveScope`

Every row now records how its live claim was made:

- `probe`: a named check in `memory/machine/live.json` passed. `liveEvidence`
  is required, the check must exist, be `pass`, and name this feature id.
- `manual`: observed through the dev `!` bridge or a human run. `liveRecord`
  must be a real path under `memory/` where the observation is written.
- `none`: not live-verified. `liveVerified` must then be false and
  `liveEvidence` is refused.

The converted matrix is **26 probe rows, 22 manual rows and 86 unverified
rows**. All 25 previously bare flags now name either a check or the record.
Three rows that were already covered by a probe check were connected to it
instead of being downgraded: `moderation.appeal-from-the-dm`
(`web-moderation-interactions`), `operations.public-api-webhooks`
(`web-webhooks`, `web-idempotency-key`) and `forms.application-forms`
(`web-component-panels`).

`features.json` gained no new table, no new dependency and no new write path.
`render-memory.mjs` now prints a `Partial` column and labels a live row with its
scope, so the generated page shows *how* it was proven, not just a green word.

## Stale rows fixed in the same pass

The plan named the form modal as open. The code says otherwise, and has since
pass 58:

- `modules/forms/src/manifest.ts` still described modal input as a later
  UI-layer concern. The comment now describes the shipped Apply → modal path.
- `memory/vault/04-Modules/forms/Spec.md` listed modal input as a non-goal.
  It is now a non-goal only for *editing* a form by modal.
- `memory/vault/01-Mission/Status.md` said "Modal input is not shipped". It now
  records the pass-58 panel, and keeps the honest limit: adapter/probe-proven,
  not a gateway click.
- `memory/vault/01-Mission/Parity-Matrix.md` said modal input and bundle
  inclusion were both open. Only the bundle row is open.
- The Status `Next` list no longer names the modal as future work.

One plan assumption was also corrected. The plan said there was "no full
delivery scheduler" for feeds. The code disagrees: `community-events.ts` polls
every registered feed on the same 60-second guild tick, honours
`feeds.pollMinutes`, and `ContentService.pollFeed` dedupes by GUID. The missing
part is the non-RSS source adapters, and the row now says exactly that.

## What we tried and rejected

- **Require a `live.json` check for every live row.** The probe can only record
  the 28 paths it drives. The other 22 rows were observed through the dev bridge
  or a human run; forcing them onto a check would either fabricate a probe
  result or delete a true observation. A written record is weaker than a probe
  and the schema now says so.
- **Keep `open` and add two arrays.** The reader still has to decide whether
  `open` means "write it" or "prove it". One status carries the distinction in
  the column a reader scans.
- **A third live scope for adapter-only rows.** The real adapter is not a live
  Discord client. An adapter-only row stays `liveVerified: false`; the note and
  the module Status page say what was driven.
- **Derive `partial` from booleans.** `shipped` plus `open` can disagree; one
  status and two arrays cannot.
- **Rewrite `features.json` by hand.** 134 rows and 48 live flags is how the
  bare flags happened. A one-shot transform added the scope mechanically, and
  the gate now enforces the result.
