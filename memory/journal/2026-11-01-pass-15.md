# Pass 15 — 2026-11-01

## What changed

- Added a **development-only prefix bridge** in `apps/bot/src/prefix.ts`. It
  parses `!command [action] [key=value ...]`, builds an `InteractionLike`, and
  calls the same `dispatchCommand` as slash commands. It is registered only for
  `DEV_GUILD_ID` outside production, so slash remains the only product surface.
- Moved the bot-authored mention allowance from a per-bot-id seam to the same
  single `DEV_GUILD_ID`, so the Discord MCP can exercise mention chat without
  copying its snowflake into `.env`. Production still ignores every bot author.
- Added `apps/bot/src/prefix.test.ts`: quote handling, action shorthand, typed
  options, bounds, unknown option, real dispatch and the other-guild gate.
- Fixed `/ticket stats`: the guild-wide branch used to run after the ticket-id
  lookup, so it only worked inside a ticket thread. It now runs before the
  lookup; `commands.test.ts` covers it outside a thread.
- Changed ready-time command sync: clear global application commands, set the
  full payload, then `fetch()` Discord's list and log missing/extra names. This
  is the server-confirmed registration the test guild needed.
- Live proof in guild `1450130465146142785`, channel `1566291983377367080`:
  `!ping`, `!about`, `!ai status`, `!mod history` and `!rank leaderboard` all
  returned real messages/embeds; a qwen3:8b mention reply landed in `#ai-chat`.
  `!ticket stats` reached the permission guard because the MCP bot lacks
  `ManageGuild`; the ordering bug was still exposed and fixed.
- Memory: new [[Live-Testing]] architecture page, decision-log rows 45–48,
  AI/community status updates, feature notes, status/roadmap/home updates.

## What we tried and rejected

- **Allowlist the MCP bot by snowflake** (`DEV_AI_TEST_BOT_ID`). Rejected: it
  required an operator to read a bot id, add an env key and keep it in sync with
  the harness. One explicitly named development guild is a smaller, clearer
  boundary and covers both mention chat and prefix commands.
- **Use a user token or patch the MCP to invoke slash commands.** Rejected: a
  user token is against Discord's terms, and patching a third-party harness
  would not prove our own interaction path.
- **Treat the MCP's empty message text as a failed embed.** Rejected after
  inspecting the channel through Discord's REST API: the messages carried the
  expected embeds. MCP `read_messages` only renders `content`; the adapter was
  fine.
- **Add a production prefix command system.** Rejected: it would be a second
  public surface, a second help system and a second permission story. The bridge
  exists only to test the one pipeline.
- **Keep `commands.set(payload)` without clearing.** Rejected for this pass: the
  user explicitly asked for a clear-then-register cycle, and the read-back gives
  a stronger log. The risk window is one ready handler and the next boot repairs
  it.
- **Call `/ticket stats` a MCP failure and move on.** Rejected: the permission
  error was real, but the ordering bug underneath it was ours. Fixed at the
  source and tested.
