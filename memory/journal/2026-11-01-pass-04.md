# Pass 04 — 2026-11-01 — P1 audit and repairs

## What changed

- **One retry policy.** `RetryPolicy`, `DEFAULT_RETRY_POLICY` and `backoffFor`
  now live in `packages/queue`; `retryOptions` (BullMQ) and `InProcessJobQueue`
  both use the same object. Previously the driver defaulted to a 10 ms backoff
  and BullMQ to 250 ms — the test described the driver, not production.
- **`/setup` proven through dispatch.** New tests block a caller without
  `ManageGuild`, allow one with it, assert the disabled-module state, and use a
  repository spy that throws on write to prove the command is read-only.
- **Restart test strengthened.** It now writes through `SettingsService` (the
  handle a command receives), closes and reopens the PGlite data directory, and
  uses `toEqual` plus `toStrictEqual` on a payload containing nested objects,
  arrays, JSON null, integers, a float, Unicode and the numeric-looking string
  `"123"`. Module isolation is exercised with two modules through the service.
- **Unknown jobs leave a receipt.** An unregistered job name now claims then
  records `failed` instead of updating a row that did not exist.
- **Telemetry no-op asserted.** The disabled test also checks that no exporter
  exists, not only that `traceparent()` is undefined.
- **Worker readiness is proven, not assumed.** The worker pings Redis with a
  bounded five-second probe before it logs `worker ready`, and redacts the URL's
  password in the error. A closed port now exits 1 instead of printing ready and
  failing later. `migrate` also prints a non-empty stack when the driver throws
  an empty message.
- **Records.** Added [[01-Mission/Status|project status]] with an eight-row
  acceptance table and an explicit proven/not-proven split; updated the setup
  status and the roadmap's P1 evidence.

## What we tried and rejected

- **Loosening the assertions until the suite passed.** The failures were real:
  the two queue numbers diverged, `/setup` had no guard test, and the restart
  test skipped `SettingsService`. Fixed the code/tests instead.
- **Calling the in-process driver "BullMQ verified".** It is not. The adapter is
  configured and unit-tested; a live worker needs a Redis server. The vault says
  so in three places.
- **Adding a fake Redis and calling the cooldown test "real".** The concurrency
  test uses an atomic in-process stand-in and is labelled that way; the store
  itself issues a single `SET NX PX`, which is the production semantics.
- **Writing a migration to run on boot just to have a demo.** Rejected; the
  compose one-shot `migrate` service and `pnpm db:migrate` remain the only path.
- **Deleting the weak `/setup` guard test without replacing it.** It now asserts
  the actual behaviour through the real dispatch pipeline.
- **Claiming the Docker image works.** No daemon exists here. The files are
  written; the build is named as unverified.
- **Letting the worker say "ready" as soon as the constructor returned.** BullMQ
  connects lazily, so that line was true only of the object, not the service.
  A bounded Redis ping now gates the message.

What is genuinely asserted now:

- 50 concurrent cooldown calls produce exactly one winner; TTL admits the next;
  the only fallback is the unconfigured one and it logs a warning.
- A transient failure takes 2 attempts and increments the effect exactly once; a
  permanent failure stops at the shared limit (3) and is recorded `failed`; a
  duplicate completed delivery is skipped; jobs dispatch by name.
- One trace id covers command, both settings repository spans, enqueue and job,
  with parent ids; the disabled telemetry has no exporter.
- `/setup` is permission-guarded, within the budget, reports all four readiness
  dimensions and writes nothing.
- The bundled worker refuses a configured-but-unreachable Redis before it
  announces readiness, and its message contains no password.

The smoke commands pin `DOTENV_CONFIG_PATH=.env.absent`; a local `.env` exists
in the working tree, but no smoke run reads or depends on it.

Still requiring a live service: BullMQ retry through Redis, Redis cooldown
atomicity, a Postgres server run, the Docker image, a gateway login, and an OTLP
collector. None is claimed.
