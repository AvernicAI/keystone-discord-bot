# Pass 16 — Public release packaging

## What changed

- Published the project as **Keystone** at
  https://github.com/RNGBubba/keystone-discord-bot (public).
- Rewrote `README.md` around the questions a new user and a new agent actually
  ask: what is needed, how to run (memory mode, full local stack, Docker), Discord
  app setup and permissions, configuration, the full command list, honest
  features, current progress, how to add a module, how an agent should read the
  repo, Obsidian setup, live testing and command sync.
- Added `AGENTS.md`: read order, the inward-kernel rule, token-free tests, the
  command-budget gate, memory-update ritual and the exact current state.
- Added `LICENSE` (**AGPL-3.0-or-later**) and set `license`, `repository`,
  `homepage` and `bugs` in `package.json`. Q-1 is now answered instead of open.
- Made command sync safe after the live rate-limit incident: boot fetches the
  server set and only clears + re-registers on name drift. `pnpm commands:sync`
  does an atomic replace; `pnpm commands:resync` does the deliberate clear →
  register → fetch verification cycle. This matches the clarified rule: clear
  the first time (or on an explicit resync), then add/update normally.
- Regenerated the four vault pages from machine truth and closed the stale-page
  failure that `pnpm check` caught.

## What we tried and rejected

- **Clear and re-register on every boot.** Rejected after a live test: Discord
  allows two global bulk overwrites per ten minutes, and the second write was
  rate-limited, leaving the app with zero commands until a manual restore. The
  boot now writes only on drift; the clear cycle is explicit.
- **Keep the MCP bot-id allowlist.** Rejected: it made the harness depend on a
  snowflake copied into `.env`. `DEV_GUILD_ID` is the single, auditable seam.
- **Publish without a licence.** Rejected: a public repo with no licence is
  all-rights-reserved, not open source. The repo already recommended AGPL-3.0;
  the owner can change it with a one-file decision.
- **Hand-edit `Feature-Status.md` and `Pass-Ledger.md`.** Rejected; the generated
  pages were stale because the machine files had moved. `pnpm memory:render` is
  the fix, and `pnpm memory:check` is the gate.
- **Make the README a feature brochure.** Rejected: the status section names the
  unproven paths (live slash interaction, pgvector ANN, live Postgres, MEE6
  fetch) instead of implying they are done.
