# Pass 78 — the dashboard people can use

**Date:** 2026-11-05
**Phase:** P7.5
**Branch:** `feat/dashboard-shell`

## What changed

The dashboard had every capability and no product surface: sixteen pages with
sixteen first impressions, a raw settings dump that listed every module's JSON,
and no way to find out what a server still needed. This pass makes the first
five minutes work, and finishes the OAuth loop that had stayed open since P6.

### Research first, including two corrections

`memory/vault/02-Research/Web-Dashboard-Benchmark-2026.md` reads the primary
docs, help centres and issue threads for MEE6, Dyno, Carl-bot, ProBot, Ticket
Tool, Wick and Statbot on 2026-11-05. Eight claims entered
`memory/machine/research.json` with sources and expiries.

Two claims in the approved plan did not survive reading:

- **Ticket Tool does not require Developer Mode or pasted ids.** Its current
  setup page uses in-dashboard channel pickers. The raw-id critique is a
  2020-era pattern, not a 2026 fact.
- **Carl-bot issue #50 is about reaction roles, not Save.** Its newest comment
  (2025-12-15) is "Every time I click save, nothing happens," and comments do
  not continue into 2026.

What did hold: MEE6, ProBot and Ticket Tool all require **Administrator**, not
Manage Server, to open their dashboards. Keystone keeps Manage Server and now
says so on the landing page. The benchmark's real opening is the first five
minutes — finding, enabling, readiness, trusting a save, and finding an id —
which is exactly what this pass builds.

### One shell and one palette

`apps/web/src/theme.ts` imports `ACCENTS` from `@keystone/ui`, so a state colour
means the same thing in a Discord panel and on a web page. `shell.ts` owns the
document: skip link, brand, account menu, breadcrumbs, guild sidebar, page
heading and a footer that stamps the read time, the storage mode and the audit
promise. Landing, guild list, overview, analytics, activity, directory,
settings, config, drift, templates, fleet, tokens, webhooks, instance and the
error pages all use it. The CSP gains only `img-src
https://cdn.discordapp.com data:` for guild icons, with an initials fallback;
there is still no script source.

### A catalog, a toggle with a receipt, and computed readiness

`module-groups.ts` groups the catalog by job (Safety, Community, Support,
Operations). Each module card has one Configure link and one enable/disable
form. `POST /dashboard/guilds/:id/modules/:module/toggle` writes through the
module's own Zod schema via `SettingsService`, appends the usual `audit_events`
row and redirects with a notice naming the module and its new state.

`readiness.ts` computes four facts from settings the bot already reads — one
module on, a log channel, welcome, a portability receipt — and links each
unfinished fact to the page that fixes it. No score, no invented health metric.

`GET /dashboard/guilds/:id/activity` renders the newest 50 audit rows for the
guild, the same rows the API reads. `GET .../directory` reads channels and roles
through a new `DirectoryPort`; it is the only new outbound Discord call in
`apps/web`, it never writes, and the page names a missing port or failed read
instead of showing an empty server.

### Bugs the browser found

1. **The sidebar icons were huge black silhouettes.** `icon()` emits an SVG with
   no size or stroke rule; the sidebar had no `.icon` sizing, so every path
   filled its container. The theme now owns one `.icon` contract (18 px,
   `fill:none`, `stroke:currentColor`) and the second browser pass confirmed it.
2. **A real Discord 429 became a 500 on the page after a save.** Every request
   called `GET /users/@me/guilds`; a burst of navigation spent Discord's
   per-user limit, and the save's redirect landed on "Request failed" even
   though the write had succeeded. `GuildAccessService` now caches the OAuth
   guild list for 30 seconds per access-token hash, shares an in-flight read and
   never caches a failure. Bot membership is still checked per guild on every
   authorize. Five tests cover the cache, the failure path and the 403s.
3. **`1 commands` on module cards and settings headers.** Fixed with the count
   in both places.
4. **`1 recent rows`** on the activity page. Fixed.
5. **Six pages rendered as raw text.** Config and drift, templates, fleet, API
   tokens, webhooks and the instance console still emitted the old `.panel`
   class, which the new stylesheet never defined. The fix is one alias rule in
   `theme.ts`, not a per-page restyle, and the same pass styled bare buttons and
   the file picker those pages use.
6. **The guild chip stacked two inline spans on one line**, so "Mr Bubba's
   server" and "Manage Server access" collided at every width. Both are blocks
   now, with ellipsis on the name.
7. **Analytics source labels collided with their bars**, and a zero row still
   drew a 2px sliver. Rows now lead with the human label, name the table beneath
   it, and draw nothing for zero.
8. **Every settings page was one "General" fieldset.** The schema's root group
   is the module itself; it now renders its fields and child groups without the
   wrapper, so 55 fields no longer sit inside a box labelled General.
9. **The toggle banner landed off-screen.** The redirect targets `#modules`, but
   the notice lived above the catalog and the sticky topbar covered the anchor.
   The banner now sits under the catalog heading and `#modules` has an 84px
   scroll margin, so the receipt is visible where the click happened.
10. **A signed-in 404 offered "Sign in with Discord".** Error pages now receive
    the resolved session and render the account menu; a regression test asserts
    both the 404 and 405 path.

### The ledger now covers the web

`memory/machine/surfaces.json` grew thirteen `web` rows covering every
`render…` export. `scripts/audit-visuals.ts` scans the exports, fails when one
has no row, requires a `/` route, requires the shell footer, bans a raw hex in a
web surface and accepts `browser` as a proof class. It runs inside `pnpm check`
and now reports 25 surfaces. Every web row carries an explicit proof class, a
date and a note that names what was not exercised; all thirteen are `browser`
from the 2026-11-06 walk, with settings save, fleet apply, token issue, webhook
send, raw actor ids and session revoke recorded as open gaps in the row itself.

### The gateway loop is proven

`pnpm web:start` served Postgres mode with real Discord OAuth configured. The
browser completed **Sign in with Discord → /auth/callback → /dashboard** against
the real Discord authorization server, not the probe's fake exchange. The
session then loaded the development guild, and the pass exercised the catalog
toggle, the activity row, the directory read and the analytics window.

## What we tried and rejected

- **A client-side framework.** No page needs client state yet; a picker is a
  server-rendered `<select>`. Adding React would mean a second render model, a
  hydration budget, a script-src exception and a supply chain for a feature not
  yet designed.
- **Copying Wick's numeric health score.** Four named facts with four fix links
  are more honest and more actionable than a percentage. A score also invites
  arguing with the number instead of fixing the setting.
- **Caching the bot-membership check too.** It would remove the last Discord
  call from a page load, but it is the security-relevant half and one guild read
  is cheap. The cache is deliberately only the OAuth guild list.
- **Resolving every actor id to a username for the activity page.** That needs
  either a bot lookup per row or a second table. The page shows the same id the
  audit ledger stores; linking it is a later pass, and the raw id is at least
  honest.
- **Adding a second analytics store for dashboard speed.** Rejected for the same
  reason as before: two counters eventually disagree. The page reads the same
  sources and names them.
- **Marking the dashboard `shipped-in-repo` earlier.** It waited for the real
  OAuth round trip, which this pass completed.
