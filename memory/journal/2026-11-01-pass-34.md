## What changed

`/setup` is now a real hub with the five names the saved plan lists:

| Subcommand | What it does | Existing seam |
| --- | --- | --- |
| `/setup status` | The previous root-only readiness report, unchanged | `HealthProbe`, the setup module's own settings |
| `/setup module` | Lists modules, inspects one, or sets `enabled` | `ConfigPort` → `SettingsService` → the module's Zod schema |
| `/setup verify` | Read-only check of database, settings parsing and the command catalog | `HealthProbe`, `ConfigPort.list`, `ctx.catalog` |
| `/setup import` | Previews an attached bundle and never applies it | `ExportPort.importBundle({ dryRun: true })`, `AttachmentReader` |
| `/setup reset` | Removes one module's stored settings so its schema defaults return | new `ConfigPort.reset` over the existing repository `clear` |

`ConfigPort` gained `reset(guildId, moduleId)`; `SettingsService` already had the
implementation, so this exposes the existing repository operation instead of
adding a store. `apps/bot/src/export-port.test.ts`'s memory `ConfigPort` gained a
throwing `reset` so the portability adapter still cannot write settings.

No new root, no new table, no migration, no paid service and no new external
dependency.

### Why import is a preview, not a second importer

`/export import` already owns attachment reading, checksum verification,
dry-run/apply and rollback. A second applying importer in `/setup` would be a
second policy and a real drift risk. `/setup import` therefore performs the
same `ExportPort` dry run, prints the counts and warnings, and says plainly that
no rows were written and that `/export import` is the applying command.

### Why verify can say "not ready"

The live window runs in memory mode, so `verify` reports `Not ready: database`
and names `DATABASE_URL`. It does **not** turn a missing database into a green
check. Settings parsing is reported separately from database readiness; the
command catalog count is the same catalog `/help` reads.

## What we tried and rejected

- **Inventing 52 subcommand names to make 160.** Rejected. There is no saved
  list; a table of invented names would be worse than an honest correction.
- **Adding an 18th root now.** Rejected; the pass explicitly forbids a new root,
  and the saved plan does not name one. The 17 live roots stay.
- **Making `/setup import` a second applying importer.** Rejected; it would
  duplicate `/export import`'s checksum, dry-run and rollback policy. A preview
  uses the same port and cannot write.
- **Letting `/setup reset` wipe cases, XP or the ledger.** Rejected. It clears
  only the selected module's settings record; the footer says so, and the PGlite
  test proves the defaults return.
- **Reporting `verify` as ready in memory mode.** Rejected. The live output names
  the database as not ready and points at `DATABASE_URL`.
- **Splitting `/setup` into five root commands.** Rejected; five subcommands cost
  zero new global slots and keep onboarding in one place.
