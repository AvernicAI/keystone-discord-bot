# Pass 12 — Intent profiles, capability report and P4.5 close

## What changed

- Added `required` vs `optionalIntents` and `intentFallbacks` to the module
  contract, with manifest validation for duplicates, required/optional overlap
  and fallbacks that name an undeclared intent.
- Added `INTENT_PROFILE=minimal|full` (default `full`) and
  `ModuleRegistry.intentsForProfile()` / `capabilityReport()`.
- Moved `GuildMembers` and `MessageContent` to optional in moderation, community
  and AI, with named consequences.
- `RuntimeHealth` now reports the capability report; `/setup` adds a **Gateway
  intents** field and a next-step branch for the minimal profile.
- Added `scripts/audit-intents.ts`; `pnpm check` now runs both audits.
- Updated README, roadmap, status, platform research, memory README and the vault
  index for the P4.5–P10 plan.

## What we tried and rejected

- **Default to `minimal` and make everyone opt in.** Rejected for this pass:
  it would silently disable welcome, autorole and the scanner for every existing
  self-host. `full` preserves behaviour; `minimal` is documented as the
  10,000-user-safe profile.
- **Retry login with `minimal` after close code 4014.** Rejected: it hides a
  configuration error and complicates shutdown. A clear boot error is teachable.
- **Report granted intents.** Not possible before login. The report says what
  was requested and names the consequence; the Portal remains the source of
  truth.
- **One fallback string per intent.** Rejected: both community and moderation
  declare `GuildMembers`; the report now joins every module's consequence.
