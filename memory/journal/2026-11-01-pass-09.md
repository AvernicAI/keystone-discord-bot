# Pass 09 — P4 economy hardening

**Date:** 2026-11-01. **Phase:** P4. **Status:** complete in-repo for the
buildable economy surface; live Discord/Postgres proofs remain open.

## What changed

- Audited the existing P3 `/rank` economy against the P4 request. It already had
  `economy_ledger`-derived balances, daily, pay, shop/buy, gamble and ledger; it
  did **not** have a safe check-then-insert path or stable retry keys.
- Added `CommunityStore.spend` and a checked debit path; `transfer` now locks a
  guild row in Postgres and serializes money mutations in the in-memory store.
- Passed the Discord interaction id through `/rank pay`, `buy` and `gamble`;
  retries dedupe to one movement. Daily also uses `ctx.cooldowns` through the
  kernel port.
- Added explicit self-pay, bot-target, transfer-cap, gamble-cap, insufficient
  funds and daily-cooldown refusals. `CommunityActions.isBot` is the adapter seam.
- Kept role purchases direct; a failed role grant is reported explicitly after
  the auditable debit. The alternative review queue is recorded in ADR-0011.
- Fixed the exposed `guilds.joined_at` schema/migration mismatch so the economy
  lock can create/fetch a guild row in PGlite.
- Added service concurrency tests, command coverage for every economy surface,
  and PGlite close/reopen plus concurrent-transfer tests.
- Updated Community Spec/Status/Teaching, parity, roadmap, project status,
  command ledger, README/indexes, AI status, system overview, decision log,
  project.json and ADR-0011.

## What we tried and rejected

- **Cached balance column.** Rejected: two truths and projection drift.
- **Command-level balance check.** Rejected: the concurrent transfer test spends
  twice from one balance.
- **New `/economy` root.** Rejected: `/rank` already owns the surface and the
  command budget is a product constraint.
- **Review queue for shop roles.** Rejected for this pass: not funded by P4 and
  adds moderator latency. Direct grant + explicit failure is documented.
- **Random UUID per retry.** Rejected: a retried interaction can move money twice.
- **Automatic AI summary on ticket close.** Not named by P4; kept on demand to
  avoid a hidden model call on every close.
- **Loosening the PGlite test or skipping the lock.** Rejected; the schema column
  mismatch was fixed instead.
