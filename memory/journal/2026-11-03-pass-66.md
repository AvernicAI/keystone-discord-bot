## What changed

- **A real memory audit.** The new audit page records the gate results, the
  machine-truth snapshot, 22 drift findings with evidence, the semantic defects
  behind them and a three-tier remediation plan. It found that the initial
  `memory:check` failure was line-ending drift, not stale content: the renderer
  writes LF while a Windows checkout can hold CRLF and the check compared bytes.
- **A proposed Roadmap v3.** The plan is built on a fresh read of the 2026
  market: the five generalists, the specialists, the open-source prior art, the
  AI-native wave and the platform shifts. It names ten moats, a domain feature
  plan, the command-budget shape, the data model, the architecture, six phases,
  launch assets, metrics, risks and a 90-day sequence. It is explicitly
  **proposed**; `project.json` still says P7 and `Roadmap` remains the active
  index until it is accepted.
- **P0 fixes.** Added `.gitattributes` (`* text=auto eol=lf`); made the
  generated-page check compare normalised line endings; corrected the README's
  stale 17-migration / 19-of-19 probe sentence; added ADR-0019 to
  `project.json`; removed the AGENTS.md clause that still called the pass-64
  appeal/verify id work open.
- **P1 corrections.** Corrected the parity tally and the rank-card, welcome and
  ticket-panel notes; corrected the Master-Plan's "no `packages/ui` yet"
  sentence; corrected the Command-Budget's "seventeen roots" and "83 slots";
  settled the Home page's licence blocker; replaced the Roadmap P7 "rest of this
  phase is open" sentence; linked both new pages from Home; added a proposed-
  successor banner to Roadmap.
- **No product change.** No module, command, table, intent, migration, test or
  live-probe check moved. The test count remains **631 in 92 files**; the last
  live probe remains **28/28**.

## What we tried and rejected

- **Rewriting the 1,244-line `Status.md` in this pass.** Rejected: it would mix a
  truth audit with a history rewrite, and the page is accurate even where it is
  hard to read. The plan schedules the restructure in P7.5 and the generated
  Pass-Ledger already holds the history.
- **Changing the feature schema (`partial`, `liveScope`) now.** Rejected: it
  needs a schema change, a migration of 134 rows and matching checks. The audit
  records the defect; the plan schedules the schema and checks together.
- **Adopting Roadmap v3 in `project.json` now.** Rejected: the plan is proposed,
  not accepted. Changing `phase` would make the machine claim a decision the
  user has not made.
- **Building the plan's features now.** Rejected: this is a planning pass; the
  first product pass is P7.5. Adding a feed table, KB table, structure snapshot
  or captcha port now would be scope without an exit demo.
- **Replacing the dashboard with a SPA/Next.js shell to fix UX.** Rejected: the
  plan proposes server-rendered HTML plus a small progressive-enhancement layer,
  and keeps a Next.js shell optional and not built. A framework is not a
  substitute for a support console, mobile layout and charts.
- **Deleting historical pages or journals.** Rejected: history is evidence. The
  plan moves long history behind the generated ledger rather than erasing it.
- **Adding all proposed tables and commands to the machine files.** Rejected:
  the command budget, data model and phases are targets, not shipped rows. The
  machine files must not contain code that does not exist.
